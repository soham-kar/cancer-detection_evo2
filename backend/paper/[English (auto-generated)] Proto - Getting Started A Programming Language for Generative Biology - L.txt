>> Proto is a high-level programming
language and tool platform for
generative biology.
The goal of Proto is to make it easier
to compose biological AI models into
design workflows without needing to
rebuild a custom pipeline for every new
task.
Many biological design campaigns depend
on a combination of sequence generators,
predictive models, scoring functions,
optimization algorithms, and downstream
analysis tools.
But these components are often difficult
to install, configure, and connect.
Proto provides a shared framework for
bringing these tools together using four
core primitives:
sequences,
constraints, generators, and optimizers.
>> When you open the prototypes tab, you
can see your existing designs.
You can also use pre-built example
programs.
In this example, we will create our own.
To start, we'll take a look at the Proto
canvas, which is the graphical interface
for building Proto programs.
The canvas lets you work with the same
four core pieces of Proto:
sequences, constraints, generators, and
optimizers,
but as visual blocks that you can
configure and connect.
This makes it easier to see the
structure of a design workflow,
what sequence you're designing, what
tools are scoring it, what model is
generating candidates, and how the
optimizer is guiding the search.
For this demo, we'll build a simple
promoter design workflow directly in the
Proto canvas.
The first primitive in Proto is a
sequence.
This is the biological sequence we want
to design or modify.
In this case, we'll use a DNA sequence
because our goal is to design a short E.
coli promoter.
To start, I'll start by dragging a DNA
sequence box onto the canvas.
This block represents the candidate
promoter sequence that the rest of the
workflow will operate on.
Within this block, you can do things
like change the length, rename the
segment,
and specify an initial sequence to start
with.
For this example, we'll use a random
sequence to start.
The next primitive is a constraint.
A constraint is a scoring function that
tells Proto whether a candidate sequence
has the properties we want.
For promoter design, we care about
whether the sequence looks promoter-like
and whether it might be likely to drive
transcription.
For the purpose of this simple demo,
I'll stick to adding basic constraints
like the presence of a -35 and -10 sigma
70 box motifs,
and the basic sequence identity metrics
like GC content.
Each constraint gives Proto one signal
about what makes a good promoter.
The third primitive is a generator.
A generator proposes new candidate
sequences for Proto to evaluate.
Here, I'll use random nucleotide
mutation as a simple generator.
Random nucleotide mutation makes small
and random edits to the DNA sequence,
which is useful for this demo because we
can start from a randomly generated DNA
sequence and explore variants till we
converge on something that best meets
our constraints.
The final primitive is an optimizer.
The optimizer coordinates the design
loop.
It takes candidates from the generator,
evaluates them with constraints, and
decides which candidates to keep.
For this example, I'll use MCMC as the
optimizer.
MCMC is a good fit here because it can
accept or reject mutations based on the
combined constraint score,
allowing the sequence to gradually move
towards better promoter candidates while
it's still exploring the candidate
sequence space.
Once these blocks are on the canvas,
I'll connect them together. The DNA
sequence is modified by the uniform
mutation generator,
scored by the promoter-related
constraints,
and optimized by MCMC.
Then, we can run this workflow and have
Proto search for promoter sequences that
better satisfy the design objective. As
you can see, the program is now running
and generating an output energy graph
demonstrating how the designs are
converging to an optimum over the number
of iterations we specified.
In addition to allowing the program to
run, you can also view sequence output
metadata for each of the generated
candidates, and inspect the outputs to
determine how well they comply with your
constraints.

Protein MPNN is an inverse folding
model. Given a fixed three-dimensional
protein backbone, it can predict amino
acid sequences that are likely to fold
into that shape.
Let's use protein MPNN to sample some
sequences that are likely to fold into
the shape of green fluorescent protein,
otherwise known as GFP.
First, we need to specify the structure

AlphaFold database.
After we have uploaded the structure, we
can visualize it in the interface.
Before we start sampling new sequences,
there's one thing we want to set up.
Right in the center of the GFP barrel,
three residues form its chromophore, the
part of the protein that actually
absorbs and emits light.
In a wild-type GFP, these are residues
serine 65,
tyrosine 66, and glycine 67.
We don't want protein MPNN to touch them
because their identities are essential
to the protein's function.
So, rather than redesigning them, we
will mark them as fixed positions.
Using the field and specifying the range
of 65 to 67 as fixed.
Protein MPNN will then redesign every
other residue around them while holding
these three exactly as they are.
We can also change any configuration
